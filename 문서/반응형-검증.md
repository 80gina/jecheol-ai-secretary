# 모바일 반응형 — 설계와 검증

평가 항목 #6 대응 문서입니다. **어떤 폭에서 무엇이 어떻게 바뀌는지**를 명세하고,
브라우저에서 직접 측정한 값을 그 아래에 기록합니다.

---

## 1. 브레이크포인트 — 네 군데에서 무엇이 바뀌나

`frontend/style.css` 에 실제로 들어 있는 미디어 쿼리입니다.
폭이 줄어드는 순서대로 읽으면 화면이 접히는 과정이 보입니다.

| 경계 | 코드 위치 | 무엇이 바뀌나 | 왜 그 폭인가 |
|---|---|---|---|
| **≤ 1100px** | `style.css:441` | 3단 레이아웃 → **1단**. 판정 카드(`.middle`)가 `order: -1` 로 **맨 위로** 올라감 | 3단을 유지하면 가운데 열이 250px 아래로 눌려 판정 문장이 두세 글자씩 끊긴다. 그럴 바엔 세로로 쌓고, **가장 먼저 봐야 할 판정 카드를 맨 위로** 올린다 |
| **≤ 1000px** | `style.css:490` | 조건 손잡이(`.knobs`) 4열 → **2열** | 손잡이는 슬라이더라 폭이 좁으면 조작 자체가 어렵다. 개수를 줄이는 대신 **각 손잡이의 폭을 지킨다** |
| **≤ 760px** | `style.css:677` | 손잡이 **1열**, SWOT 4분면 → **1열**, 분포 막대에서 최고값 열(`.dist-hi`) **숨김**, 플래너 여백 축소 | 이 폭부터는 손가락 조작이 기본이다. 정보를 줄이지 않고 **세로로 늘어놓되**, 화면에서 가치가 가장 낮은 열 하나(최고값)만 감춘다 |
| **≤ 700px** | `style.css:447` | 시세판 표의 **머리행(`.board-head`) 숨김**, 각 행을 `1fr auto auto` **2줄 구조로 접음** | 5칸짜리 표를 390px에 억지로 밀어 넣으면 숫자가 겹친다. 머리행을 지우고 행마다 이름·값·증감을 2줄로 접으면 **가로 스크롤 없이** 읽힌다 |

### 설계 원칙 세 가지

1. **가로 스크롤을 만들지 않는다.** 폭이 모자라면 줄이는 게 아니라 **접는다**.
   표는 머리행을 버리고 행을 2줄로, 격자는 열 수를 줄여 세로로 쌓는다.
2. **먼저 볼 것을 위로 올린다.** 1단으로 접힐 때 판정 카드가 `order: -1` 로 맨 위에 온다.
   데스크톱에서 가운데 있던 것이 모바일에서 맨 아래로 밀리면 안 된다.
3. **정보를 지우는 것은 마지막 수단이다.** 실제로 숨기는 것은 두 가지뿐 —
   시세판 머리행(각 행에 이름이 남아 있어 없어도 읽힌다)과 분포 막대의 최고값 열.

### 다크 모드 — 3단 정의

`style.css:10~40` 에 색을 세 곳에서 정의합니다. 하나라도 빠지면 한쪽이 깨집니다.

| 정의 위치 | 언제 적용되나 |
|---|---|
| `:root` | 기본값 (밝은 화면) |
| `@media (prefers-color-scheme: dark)` + `:root:not([data-theme="light"])` | OS를 어둡게 써둔 경우. `:not()` 가드가 있어 **화면에서 밝게 고르면 OS 설정을 이긴다** |
| `:root[data-theme="dark"]` | 화면의 토글로 직접 어둡게 고른 경우 |

2번만 있으면 토글이 안 먹고, 3번만 있으면 OS 설정을 무시합니다.

## 2. 측정 방법 — 누구나 다시 확인할 수 있게

스크린샷 대신 **숫자로 기록**합니다. 이미지는 검색도 재현도 안 되지만,
아래 절차는 누구든 5분이면 같은 값을 얻습니다.

1. 배포된 프론트엔드를 엽니다 — <https://jecheol-ai-secretary.vercel.app>
2. **F12** → 왼쪽 위 **기기 툴바**(휴대폰 아이콘, `Ctrl+Shift+M`) 켜기
3. 상단에서 해상도를 고릅니다 (iPhone SE / iPhone 12 Pro / iPad / Responsive 1440)
4. **Console** 탭에 아래 스니펫을 붙여넣고 Enter
5. 출력된 한 줄을 3절 표에 그대로 붙입니다

```js
(() => {
  const d = document.documentElement;
  const sw = Math.max(d.scrollWidth, document.body.scrollWidth);
  const over = [...document.querySelectorAll('*')]
        .filter(e => e.getBoundingClientRect().right > d.clientWidth + 1).length;
  const vis = s => { const e = document.querySelector(s);
        return e ? getComputedStyle(e).display !== 'none' : null; };
  const cols = s => { const e = document.querySelector(s);
        return e ? getComputedStyle(e).gridTemplateColumns.split(' ').length : null; };
  console.log(`| ${d.clientWidth}×${window.innerHeight} | ${sw} | ${sw > d.clientWidth + 1 ? '있음 ❌' : '없음 ✅'}`
    + ` | ${over} | ${cols('.layout')} | ${cols('.knobs')} | ${vis('.board-head') ? '보임' : '숨김'}`
    + ` | ${document.querySelectorAll('svg').length} | ${document.querySelectorAll('button').length} |`);
})();
```

각 열의 뜻:

| 열 | 뜻 | 합격 기준 |
|---|---|---|
| 뷰포트 | 실제 측정된 폭×높이 | — |
| scrollWidth | 문서의 전체 가로 길이 | 뷰포트와 같아야 한다 |
| 가로 스크롤 | 옆으로 밀리는가 | **없음** |
| 넘친 요소 | 오른쪽 경계를 벗어난 요소 수 | **0** |
| layout 열 | 주 레이아웃 열 수 | 1100px 이하에서 **1** |
| knobs 열 | 조건 손잡이 열 수 | 1000px 이하 **2**, 760px 이하 **1** |
| board-head | 시세판 머리행 | 700px 이하 **숨김** |
| svg / button | 그래프·조작 버튼 개수 | 폭이 줄어도 **개수가 줄지 않아야** 한다 (기능이 사라지지 않았다는 뜻) |

## 4. 모바일에서 주요 기능이 되는가 — 조작 확인

레이아웃이 접히는 것과 **기능이 되는 것**은 다른 문제입니다.
390px 폭에서 아래를 직접 눌러 확인합니다.

| # | 조작 | 확인할 것 | 결과 |
|:-:|---|---|:--:|
| 1 | 질문 입력 후 전송 | 입력창이 가려지지 않고, 키보드가 올라와도 전송 버튼이 눌린다 | ◻ |
| 2 | 「조건으로 고르기」 슬라이더 | 손가락으로 끌 수 있고, 값 표시가 손에 가리지 않는다 | ◻ |
| 3 | 「서버 추천」 버튼 | 결과 카드가 한 열로 쌓여 나오고 가로로 밀리지 않는다 | ◻ |
| 4 | 시세판 스크롤 | 표가 2줄로 접혀 있고 품목명·값·증감이 모두 읽힌다 | ◻ |
| 5 | 그래프 영역 | SVG가 폭에 맞춰 줄어들고 축 라벨이 겹치지 않는다 | ◻ |
| 6 | 다크 모드 토글 | 토글 후 배경·글자·그래프 색이 함께 바뀐다 | ◻ |
| 7 | 내보내기(CSV/JSON) | 다운로드가 시작된다 | ◻ |
